1. The system shall allow users to register using a unique username within the local network.

5. The system shall maintain an availability of at least 99% during operation.
6. The application shall be compatible with Windows and Linux operating systems.

10. The system shall preserve the integrity of messages during transmission and reception.
11. The application shall start in less than 10 seconds.
12. The system shall automatically recover from temporary server connection failures.
13. The source code shall be documented according to a documentation standard established by the development team.

### Algorithm Design

1. **COMPUTATIONAL PROBLEM IDENTIFICATION:**

   The system requires solutions for several computational problems:

   - **User Authentication:** Securely managing user logins, ensuring username uniqueness, and efficient credential validation.
   - **Message Routing and Delivery:** Efficiently routing messages between users, especially in group chats, to ensure timely delivery within two seconds.
   - **Group Management:** Creating groups, managing memberships, and distributing messages effectively.
   - **File Transfer:** Secure file transfer with AES encryption, handling integrity checks and size constraints.
   - **Real-Time Notifications:** Promptly triggering notifications for new messages or system events.
   - **Concurrency Handling:** Supporting up to 50 concurrent users efficiently without performance degradation.
   - **Session Management:** Maintaining active sessions and invalidating them upon logout or inactivity.

2. **ALGORITHM CANDIDATES:**

   - **User Authentication:**
     - **bcrypt** for password hashing due to its resistance to brute force attacks.
     - **JWT (JSON Web Tokens)** for session management, providing stateless authentication.

   - **Message Routing and Delivery:**
     - **Publish-Subscribe Pattern** using topics for group chats to efficiently distribute messages.
     - **WebSocket Protocol** for real-time communication, ensuring immediate notifications.

   - **Group Management:**
     - **Distributed Hash Table (DHT)** for efficient membership management and message distribution in groups.

   - **File Transfer:**
     - **AES Encryption in CBC mode with HMAC** for secure file transfer, ensuring integrity and confidentiality.

   - **Concurrency Handling:**
     - **Thread Pools** or **Asynchronous I/O** to manage multiple connections efficiently without blocking.

3. **MCTS SEARCH STRATEGY:**

   Monte Carlo Tree Search is applied to evaluate the suitability of each algorithm by simulating different scenarios:

   - **Password Hashing:** Weighing bcrypt against scrypt based on computational overhead and security.
   - **Message Routing:** Comparing flood vs. selective forwarding algorithms for efficiency under varying network conditions.
   - **File Transfer:** Assessing encryption methods considering performance and security.

4. **SELECTED ALGORITHMS:**

   - **bcrypt (Password Hashing):**
     - *Purpose:* Securely hash user passwords to prevent brute force attacks.
     - *Inputs:* Plaintext password, salt.
     - *Outputs:* Hashed password.
     - *Complexity:* O(n) where n is the computational work factor.
     - *Advantages:* High security against brute force and dictionary attacks.
     - *Limitations:* Higher computational cost compared to weaker algorithms.

   - **JWT (Session Management):**
     - *Purpose:* Manage user sessions securely and efficiently.
     - *Inputs:* User credentials, secret key.
     - *Outputs:* Signed token containing user claims.
     - *Complexity:* O(1) for token generation and validation.
     - *Advantages:* Stateless, reduces server load, easy to implement across services.
     - *Limitations:* Requires secure storage of the secret key.

   - **Publish-Subscribe Pattern (Message Routing):**
     - *Purpose:* Efficiently route messages to multiple recipients in group chats.
     - *Inputs:* Message content, recipient topics.
     - *Outputs:* Delivered messages to all subscribed users.
     - *Complexity:* O(1) for message publication and subscription management.
     - *Advantages:* Scalable, efficient for broadcasting messages.
     - *Limitations:* May require additional infrastructure for topic management.

   - **AES Encryption with HMAC (File Transfer):**
     - *Purpose:* Securely transfer files ensuring integrity and confidentiality.
     - *Inputs:* File data, encryption key, HMAC key.
     - *Outputs:* Encrypted file, HMAC signature.
     - *Complexity:* O(n) where n is the file size.
     - *Advantages:* Strong encryption and integrity checks.
     - *Limitations:* Requires secure key exchange mechanisms.
